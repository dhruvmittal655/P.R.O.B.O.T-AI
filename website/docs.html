1. Codebase & Directory Structure

The application is structured into decoupled modules separating data extraction, persistence, UI rendering, and AI querying:

ProBot-AI/
├── main.py                 # Application launcher & dependency validator
├── gui.py                  # CustomTkinter graphical desktop interface
├── searcher.py             # Wikipedia OpenSearch & search suggestion query client
├── downloader.py           # Multi-source scraper (Wikipedia, arXiv, tutorials)
├── notes_generator.py      # Linguistic parser, sentence ranker & keyword counter
├── database.py             # SQLite ORM wrapper for articles, history & chunks
├── ai_assistant.py         # Ollama interface for phi3:mini local LLM chat
├── citation_formatter.py   # APA, BibTeX, IEEE citation builder
├── requirements.txt        # Pinned Python package dependencies
├── data/
│   └── knowledge.db        # Primary SQLite database file
├── images/                 # Downloaded article thumbnails cache
└── website/                # Web showcase, live extractor & documentation

2. Python Modules Breakdown

main.py — Entry Point & Verification

Validates that all eleven required Python dependencies can be resolved before launching the graphical interface. If any module is missing, it prints an explanatory error message pointing to requirements.txt instead of crashing silently.

searcher.py — Wikipedia Query Engine

Handles live web queries. Uses Wikipedia's OpenSearch REST API (https://en.wikipedia.org/w/api.php?action=opensearch) with custom User-Agent headers to retrieve top matching article titles, summaries, and suggestion chips.

downloader.py — Multi-Source Aggregator

Expands topic searches beyond Wikipedia. When a programming topic is detected (e.g. Python, SQL, Machine Learning), it queries technical platforms such as GeeksforGeeks and academic repositories like arXiv, parsing HTML into structured study chunks.

notes_generator.py — Extractive Summarizer

Implements algorithmic text summarization without requiring an active internet connection. Cleans citation annotations, extracts introductory overviews, filters English stop words, counts word frequencies, and constructs revision prompts.

database.py — SQLite Persistence Layer

Manages database connections, schema migrations, full-text storage, favorite toggles, and view count tracking. Employs parameterized queries to safeguard data integrity.

ai_assistant.py — Local Ollama Orchestration

Connects to a local Ollama daemon over http://localhost:11434. Sends prompt contexts derived from the currently opened article or research pack to phi3:mini, ensuring user inquiries never leave the local environment.

4. SQLite Database Schema (knowledge.db)

Data is stored locally in data/knowledge.db across four primary relational tables:

-- Primary Articles Table
CREATE TABLE IF NOT EXISTS articles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT UNIQUE NOT NULL,
    content TEXT NOT NULL,
    summary TEXT,
    topic TEXT,
    source_url TEXT,
    word_count INTEGER,
    view_count INTEGER DEFAULT 0,
    is_favorite INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Search and Access History
CREATE TABLE IF NOT EXISTS history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    article_id INTEGER,
    query TEXT,
    accessed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(article_id) REFERENCES articles(id) ON DELETE CASCADE
);

-- Multi-Source Research Packs
CREATE TABLE IF NOT EXISTS research_sources (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    topic TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Chunks Associated with Research Packs
CREATE TABLE IF NOT EXISTS research_chunks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source_id INTEGER,
    title TEXT,
    content TEXT,
    FOREIGN KEY(source_id) REFERENCES research_sources(id) ON DELETE CASCADE
);

5. Offline Fallback Mechanics

When internet connectivity is disconnected:

  • Local Search: Searching searches against articles.title and articles.content in SQLite rather than making network requests.
  • Image Rendering: The app renders previously cached JPEG/PNG files from the local images/ folder.
  • Study Notes: The rule-based algorithm in notes_generator.py operates purely in-memory with zero network overhead.
  • Local LLM Q&A: Ollama runs as a local background daemon on 127.0.0.1:11434, meaning model inference continues with full capability offline.

6. Troubleshooting & Diagnostics

Ollama Connection Error (AI Chat Unavailable)

Verify that the Ollama service is actively running on your system by executing ollama list in your terminal. Ensure the phi3:mini model has finished downloading.

SpaCy Model Missing (Can't find model 'en_core_web_sm')

Run python -m spacy download en_core_web_sm within the active virtual environment to download the required English linguistic model.

Corrupted Local Database

If data/knowledge.db becomes corrupted, delete or rename the file. ProBot AI will automatically initialize a fresh, schema-compliant database upon the next start.
